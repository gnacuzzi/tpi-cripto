# Modulo `gf257`

Nota interna para usar `include/gf257.h` / `src/gf257.c` desde el resto del TP.

## Contrato general

El modulo implementa operaciones en el cuerpo finito modulo `257`.

Regla practica:

- `gf257_normalize` se usa cuando tenes un entero cualquiera y queres llevarlo a `0..256`.
- `gf257_add`, `gf257_sub`, `gf257_mul`, `gf257_pow`, `gf257_inverse` y `gf257_div` esperan valores ya normalizados, o sea `0..256`.
- Todas las funciones que devuelven un elemento del cuerpo devuelven un `uint16_t`, porque el valor `256` es valido en el campo aunque no entre en `uint8_t`.

No guardar directamente un resultado `uint16_t` en un byte de sombra sin chequear antes que no sea `256`.

## Header

```c
#include "gf257.h"
```

Compilar con:

```bash
cc -Iinclude ...
```

El `Makefile` ya usa `CPPFLAGS := -Iinclude`.

## Funciones

### `gf257_normalize`

```c
uint16_t gf257_normalize(int64_t value);
```

Uso: convertir un entero cualquiera al representante modulo `257`.

Ejemplos:

```c
gf257_normalize(257);   // 0
gf257_normalize(258);   // 1
gf257_normalize(-1);    // 256
gf257_normalize(514);   // 0
```

Esta funcion acepta `int64_t` para poder usarla con resultados intermedios grandes o negativos. Es la funcion adecuada si venis de una resta, una suma acumulada, o una formula de interpolacion que puede dar negativo antes de reducir.

### `gf257_add`

```c
uint16_t gf257_add(uint16_t a, uint16_t b);
```

Suma dos elementos del campo.

```c
uint16_t c = gf257_add(200, 100); // 43
```

No hace validacion explicita de que `a` y `b` esten en `0..256`. La responsabilidad es del caller.

### `gf257_sub`

```c
uint16_t gf257_sub(uint16_t a, uint16_t b);
```

Resta dentro del campo. Maneja el caso en que la resta da negativa.

```c
uint16_t c = gf257_sub(3, 5); // 255
```

Conviene usarla siempre en vez de hacer `a - b` manualmente, porque `uint16_t` no representa negativos como queremos.

### `gf257_mul`

```c
uint16_t gf257_mul(uint16_t a, uint16_t b);
```

Multiplica y reduce modulo `257`.

```c
uint16_t c = gf257_mul(16, 16);   // 256
uint16_t d = gf257_mul(256, 256); // 1
```

El resultado puede ser `256`, asi que no castear a `uint8_t` sin revisar.

### `gf257_pow`

```c
uint16_t gf257_pow(uint16_t base, uint16_t exponent);
```

Calcula potencia modulo `257`.

```c
uint16_t x2 = gf257_pow(x, 2);
uint16_t x3 = gf257_pow(x, 3);
```

Se puede usar para evaluar polinomios, aunque para performance despues probablemente convenga Horner en `polynomial.c` y no llamar a `pow` para cada termino.

### `gf257_inverse`

```c
bool gf257_inverse(uint16_t value, uint16_t *out);
```

Calcula inverso multiplicativo.

Devuelve:

- `true` si pudo calcularlo;
- `false` si `value == 0` o si `out == NULL`.

Ejemplo:

```c
uint16_t inv;

if (!gf257_inverse(denominator, &inv)) {
    // denominator era 0 o el puntero era invalido
    return false;
}
```

No existe inverso de `0`. En recuperacion, si aparece una division por cero, normalmente significa que se estan usando dos sombras con el mismo numero `x` o que se armo mal el sistema.

### `gf257_div`

```c
bool gf257_div(uint16_t numerator, uint16_t denominator, uint16_t *out);
```

Divide como:

```text
numerator * inverse(denominator)
```

Devuelve `false` si `denominator == 0` o `out == NULL`.

Ejemplo:

```c
uint16_t quotient;

if (!gf257_div(y, denominator, &quotient)) {
    return false;
}
```

## Como usarlo para evaluar un polinomio

Para un bloque de `k` coeficientes:

```text
a0, a1, ..., a(k-1)
```

el polinomio es:

```text
f(x) = a0 + a1*x + a2*x^2 + ... + a(k-1)*x^(k-1)
```

Una forma directa de implementarlo seria:

```c
uint16_t y = 0;

for (size_t i = 0; i < k; i++) {
    uint16_t term = gf257_mul(coefficients[i], gf257_pow(x, (uint16_t)i));
    y = gf257_add(y, term);
}
```

Pero para `polynomial.c` conviene implementar Horner:

```c
uint16_t y = coefficients[k - 1];

for (size_t i = k - 1; i > 0; i--) {
    y = gf257_mul(y, x);
    y = gf257_add(y, coefficients[i - 1]);
}
```

Ventajas de Horner:

- menos multiplicaciones;
- no necesita `gf257_pow`;
- menos superficie para errores.

## Como chequear el valor 256 en distribucion

Cuando se evalua el polinomio para cada sombra:

```c
uint16_t y = polynomial_evaluate(coefficients, k, shadow_number);
```

antes de guardarlo como byte:

```c
if (y == 256) {
    // No se puede guardar en uint8_t.
    // Hay que ajustar el primer coeficiente no cero y recalcular.
}

uint8_t shadow_byte = (uint8_t)y;
```

El modulo `gf257` no resuelve esta regla del paper. Eso deberia vivir en `polynomial.c` o `sharing.c`, porque depende del algoritmo de distribucion.

## Como usarlo en Lagrange/interpolacion

En recuperacion vamos a tener puntos:

```text
(x_i, y_i)
```

donde:

- `x_i` es el numero de sombra, leido de metadata;
- `y_i` es el byte extraido por LSB;
- ambos se usan como valores modulo `257`.

Cada vez que haya una division en Lagrange, usar `gf257_div`.

Ejemplo de patron:

```c
uint16_t denominator = gf257_sub(x_j, x_m);
uint16_t factor;

if (!gf257_div(numerator, denominator, &factor)) {
    return false;
}
```

Si `denominator` da cero, significa que `x_j == x_m`. Eso no deberia pasar con sombras validas: dos archivos no deberian tener el mismo numero de sombra.

## Errores que este modulo no valida

`gf257` es deliberadamente chico. No valida:

- que `a`, `b`, `base`, `numerator` o `denominator` sean menores que `257`;
- que un valor pueda guardarse como byte;
- que los numeros de sombra sean unicos;
- que `k` y `n` cumplan la consigna.

Eso corresponde a `validation`, `polynomial`, `sharing` o `reconstruction`.

Si un caller tiene un entero externo o dudoso, primero debe llamar a:

```c
uint16_t value = gf257_normalize(raw_value);
```

## Tests actuales

`tests/test_gf257.c` prueba:

- normalizacion de valores chicos, negativos y grandes;
- suma, resta y multiplicacion con casos borde;
- clausura de operaciones;
- identidades (`a + 0`, `a - a`, `a * 1`, etc.);
- potencia;
- Fermat: `a^256 = 1` para todo `a != 0`;
- inversos para todos los valores `1..256`;
- division para todos los numeradores y denominadores no cero;
- errores esperados con division/inverso por cero y punteros `NULL`.

Para correr:

```bash
make test
```

## Decision de diseno actual

Por ahora `gf257_inverse` busca el inverso por fuerza bruta entre `1..256`.

Eso es aceptable para este TP porque:

- el campo tiene solo 257 elementos;
- `k <= 10`;
- las operaciones son simples;
- reduce el riesgo de implementar mal Euclides extendido.

Si despues el profiler mostrara que esto molesta, se puede cambiar internamente por Euclides extendido o una tabla precalculada sin cambiar la API.
